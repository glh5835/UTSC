## 一 使用场景与完成标准

演示者在自己的 Windows 电脑启动应用，不配置招聘 API 或模型密钥。学生选择方向与地区，看到一份明确标注日期的招聘样本，比较两个方向，填写自述技能或保持空白，最后获得最多三个可开始的学习或实践行动，并可下载结果。

首版服务于现场演示和单机探索。数据维护与学生演示在同一台电脑分时进行，不建设服务器账号、远程访问或公开网站。课程与岗位外链可以手动打开；断网时保存的说明、来源文本和核心操作仍可用。

下述完整页面和资源数量仍为目标规格。契约为 utsc-contract-1.0；MVP-03 已在固定 SYNTHETIC 分析快照上验证概览、比较、筛选和来源展开，116 项测试与桌面/窄屏浏览器检查通过；MVP-04 已完成 15 门官方课程的代理核对与离线阅读，另有 2 个自编练习、6 个待审入口、0 个真实精选活动；MVP-05 的会话画像和最多三个规则行动已通过 SYNTHETIC 自述及现有 AGENT 核对资源验证；不输出报名、匹配分或录用概率。A03 仅样例算法与逐条答案核对通过；真实批次未取得、A04 真人复核未开展，其余按阶段子项记录。

## 三 页面和交互

### 3.1 全局区域

学生页面统一显示产品名称、数据模式、快照版本、历史覆盖期和采集日期，另提供“数据说明”。历史数据不能显示为实时市场。首版默认英文主界面，保留课程与岗位原名，中文用于开发文档；双语切换后置。

地区默认 Toronto GTA；可选 Montreal Metro、Other Canada 和 All Canada。All Canada 是现有分组在加拿大范围内的合计，不代表覆盖加拿大所有岗位。职业阶段提供 All、Internship or Co-op、New Graduate、Entry Level。角色使用现有五类方向。

Toronto GTA 等分组沿用固定版本中的城市映射，并在数据说明中列出实际城市清单；未匹配城市不能静默归入 GTA。筛选条件在页面切换时保留，比较页的角色选择与个人目标角色分别保存，避免相互覆盖。

### 3.2 市场概览

输入为角色、地区、职业阶段。输出包括去重岗位数、可分析正文数、描述不足数、角色分布、技能提及数量和提及率，以及岗位样本明细。

岗位明细显示标题、机构、地区、阶段、发布日期、原始来源和纳入状态；可展开技能匹配的原文片段。点击图表不是首版必须的筛选方式，标准控件要能完成相同操作。默认不展示薪资或雇主竞争排名，避免引入不必要数据口径。

没有匹配岗位时保留筛选控件，说明当前快照无样本并提供重置筛选，不显示假的零百分比。单组少于 20 条时展示探索性提示和实际分母。

### 3.3 方向比较

用户选择两个不同角色，地区、阶段与快照相同。页面展示两侧岗位数、可分析正文分母、技能提及计数与百分比，共同出现技能，以及仅某一侧检出的技能。

“仅一侧检出”描述当前规则和样本，不命名为该职业独有技能。两侧都有分母时，可展示提及率的百分点差；任一侧分母为零时差值不可用。选择相同角色时提示更换，不生成重复图表。

比较页能跳转到“我的能力与下一步”并预选其中一个目标角色；跳转不向个人画像自动填入技能。

### 3.4 我的能力与下一步

表单包括目标角色、希望探索的阶段、技能及自述状态、已修课程、项目或志愿经历。地区沿用全局筛选。自述状态包含“学过”“有实践经历”“想练习”；不要求学生填写全部技能。课程和经历是可选文本，用于展示用户上下文，首版不自动从长文本推断技能。

用户点“生成下一步”后，根据当前输入计算结果；修改相关输入后标记旧结果需更新，避免显示成最新建议。切换页面不丢失当前会话表单。单独提供“清空本次画像与结果”，清空相关表单、路径及待导出内容，不删除公共资源或审核记录。

结果分为用户自述技能、样本提及技能、建议探索的技能三个区域。空白画像进入新生路径；有经历用户可优先选择自己想练习的技能。若目标方向无岗位样本，明确无法生成市场对照，但仍可浏览经核对的通用入门资源。

每次最多三个行动，展示建议原因、第一步、预期练习产出、资源或项目、适用条件和来源。输入或数据版本变化后，导出也必须使用重新计算的结果。

### 3.5 课程与实践

目录可按技能、资源类型和入门阶段筛选。资源类型包括正式课程、学校实践项目、官方信息入口，以及本项目编写的练习项目。每条显示名称、提供方、描述、目标技能、先修或参与条件、来源、核对日期和当前状态。

正式课程的“目录中存在”“本学期开设”和“用户符合先修”分别记录。只核实前一项时不能写成后两项均满足。练习项目可给出整理公开数据、制作图表、协作展示等产出目标，但必须标记为本项目设计。

精选活动作为目录中的补充区域。卡片包含组织、活动类型、开始及截止时间、地点或线上方式、报名入口、最后核对时间。过期条目可供查看历史，但不进入当前行动。没有有效活动时显示空状态和官方查找入口，不影响课程与实践路径。

### 3.6 数据与审核

学生模式只读展示数据来源、批次、字段覆盖和限制。维护模式由本地启动参数明确打开，提供岗位分类、资源映射和活动状态的审核操作。

维护人员可筛选待审记录、查看原始依据、修改标签、保存原因，再显式发布。审核记录至少包括对象 ID、旧值、新值、理由、审核人或本地维护标识、时间和规则版本。保存不等于已发布；学生页面继续使用原有效快照，直到发布成功。

本地开关只用于区分演示与维护入口，不声称是账号认证或多人权限控制。维护模式也只监听本机。

## 四 数据契约

### 4.1 数据模式

| 模式 | 内容 | 可以证明的能力 | 不能证明的结论 |
| --- | --- | --- | --- |
| HISTORICAL | 来源及使用范围明确的真实历史岗位和已核对资源 | 在该历史快照上的统计、对照与路径 | 当前仍在招聘、全部市场覆盖或录用概率 |
| SYNTHETIC | 人工编写的计算和交互样例 | 流程、空状态和算法正确性 | 真实市场需求或真实活动存在 |

两种模式各有独立 manifest 和数据目录，切换后清理旧统计与路径结果；个人自述可保留，但不能继续显示旧模式生成的建议。严禁把合成岗位加入历史快照或用隐藏样例填补某个地区。

### 4.2 最小对象

| 对象 | 主要字段 | 校验要求 |
| --- | --- | --- |
| 数据清单 manifest | snapshot_id、data_mode、源文件与哈希、源批次、采集区间、构建时间、词典与规则版本、使用状态 | 区分历史发布日期与处理时间；完整数据才能发布 |
| 岗位 job | job_id、标题、机构、国家、城市、market_area、正文、原始链接、发布日期、采集时间、源文件位置 | 缺 ID 隔离；正文缺失不补造；国家与时间错误有原因 |
| 分类结果 classification | job_id、角色、阶段、匹配依据、审核状态、排除原因 | 原始提取值与审核值分开，不覆盖 raw |
| 技能提及 skill_mention | job_id、skill_id、原始词、原文片段或位置、规则版本 | 同岗位同技能计一次；别名共用标准 ID |
| 技能字典 skill | skill_id、显示名、别名、匹配规则、版本 | 同 ID 不重复；缺词典版本不能宣称可复算 |
| 资源 resource | resource_id、类型、名称、提供方、描述、入门等级、来源、核对时间、先修与开放状态 | 未知状态保留未知，不自动变成可参加 |
| 映射 resource_skill | resource_id、skill_id、关系、来源依据、审核状态 | 能解释对应关系；未核对映射不进入自动行动 |
| 活动 opportunity | opportunity_id、组织、名称、链接、开始及截止时间、时区、时间精度、核对状态 | 无明确活动日期或核对状态时不作立即报名推荐 |
| 画像 profile | 目标角色、阶段、技能状态、课程与经历自述 | 当前会话；不写公共数据库、日志或测试截图 |
| 审核 review | 对象、修改内容、理由、审核标识、时间、状态 | 可重开；修改来源内容后标记需重新核对 |
| 发布 release | 发布版本、岗位快照、资源版本、映射版本、审核版本、上一版本 | 比较与路径同时读取相同发布包，支持回退 |

以上为需求级字段摘要；MVP-00 已在数据契约中明确最小类型、约束与枚举。由于尚未取得真实批次，该契约不表示已验证上游字段兼容；后续逐字段适配并保持兼容或显式迁移。实现时可用 JSONL 与 SQLite 组合，不要求为了每种对象创建一个文件或数据表。

### 4.3 去重与纳入规则

同一 job_id 的重复记录按有效采集时间取较新版本并保留命中历史；同一采集时点的关键字段冲突则隔离待审，不静默任选。缺 ID、非加拿大、无效或未来发布日期按固定批次规则排除并记原因。岗位年龄继续用原始采集时间作为历史筛选基准，不用今天重写历史样本。

角色或阶段有歧义、资深标题及初级标题与多年经验冲突的记录先进入待审，不进入正式统计。短正文单独记录。首版“正文可分析”采用清理后至少 100 个 Unicode 字符且为可读正文的默认规则；MVP-00 已固定清理与计数方式。上游实际阈值仍待取得配置后核对，不和旧口径混用却不说明。

进入正式样本需要字段校验通过且没有阻断性待审问题。正文不足的岗位可在质量页查看，但不作为技能率分母。保留“筛选候选数、正式岗位数、可分析正文数、排除及待审数”，对每层含义作简短说明。

## 五 行动生成规则

首版不使用模型或综合匹配分。规则按以下顺序处理：

1. 获取所选角色、地区、阶段的同一发布快照，计算技能提及数量及分母。
2. 用户明确选择“想练习”的技能优先；没有选择时，取样本中提及较多、用户尚未自述有实践经历的技能作为探索候选。这个选择只说明可以探索，不称作用户不会。
3. 只使用已审核的技能资源映射。与目标技能直接相关且适合入门或当前阶段的资源优先；并列按固定 resource_id 排序，保证可重现。
4. 条件已知不满足的资源不给“现在报名”动作；条件未知则显示待确认和核实入口。经设计的本地练习项目可以成为独立第一步，不假设外部项目可参加。
5. 合并重复资源，最多展示三个行动；不足三个就展示实际数量，没有合适资源时解释缺口并提供可核实入口。

空白画像优先展示入门路径；已有经历画像优先响应其“想练习”的技能。目标分组无样本时不计算市场差距，只展示明确标作通用探索的已核对资源。资源或活动状态按演示时的当前时间判断，不能因为历史岗位快照冻结就冻结活动有效期。

课程与活动使用 America/Toronto 时区处理本地日期，不硬编码固定 UTC 偏移。只给出截止日期而无时刻时展示日期精度，不编造具体时间。年份或时区不能确认的活动进入待确认区。

## 六 保存 导出与失败状态

个人画像只保留当前浏览器会话；页面切换可保留，清空、新会话或服务重启后不自动恢复。公共数据和审核应持久化，重启可重开。自动日志不记录个人自由文本；测试使用独立样例而非真实学生经历。

导出至少提供 Markdown 行动摘要及 CSV 统计或比较结果。行动摘要包含目标、用户自述、建议依据、技能计数与分母、资源链接、数据模式、发布版本和日期；CSV 不把未检出或缺失写成有依据的零。实现时防止用户文本在 CSV 中被解释成公式。

| 异常 | 期望行为 |
| --- | --- |
| 本地数据不存在 | 显示需要导入固定数据，不自动调用 API 或回落至隐藏合成模式 |
| 文件损坏或结构错误 | 给出可定位错误，保留原有效发布版本 |
| 角色、地区或阶段无样本 | 显示无样本，保留控件，允许重置或换条件 |
| 历史岗位可能已过期 | 保留历史样本说明，不宣称当前开放 |
| 资源条件或日期不明 | 待确认，不作为立即参加行动 |
| 保存审核或发布失败 | 保留旧版本及用户编辑，说明失败位置 |
| 下载前输入已变化 | 要求更新结果，导出重新计算后的版本 |
| 断网打开外部链接失败 | 核心页面继续可用，来源 URL 和本地说明保留 |

## 七 首版验收数据与演示脚本

人工测试样例应覆盖重复 ID、缺 ID、无正文、短正文、无效日期、少样本分组、无样本方向、同技能重复提及、技能别名、冲突分类，以及过期和未知日期活动。样例要有独立预期结果，不能由被测函数重新生成答案。

历史数据演示需报告实际导入数量、正式样本数量、人工复核数量、角色与阶段一致率、资源核对数量和限制。内容目标 15–25 条，最低为 10 条经核对课程或实践资源；活动不设最低数量。达不到真实数据或资源条件时如实交付阶段结果，不生成假来源补足。

记录复核执行者与方法；开发代理逐条检查不冒充用户或朋友的人工审核，人工复核未开展时保留待完成状态。

最终现场演示建议按以下任务进行：

1. 启动后展示模式、数据日期和来源，确认无需密钥。
2. 选择 Toronto GTA 和一个有样本阶段，查看概览并比较两个方向；若样本不足展示其限制。
3. 使用空白画像生成入门行动，说明每条建议依据。
4. 加入一项实践经历和一项想练习技能，更新并观察建议变化。
