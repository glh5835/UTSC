## 三、实现范围

### 3.1 本地经历抽取

`web/src/lib/skillExtraction.ts` 实现规则集 1.0.0：

- 按 sentence 保留原文 `evidence_text`，匹配共享技能目录的 label／aliases；
- 大小写不敏感、词边界匹配，多个别名在同一句同一技能只产生一个候选；
- 输出 `skill_id`、`interpretation`、`evidence_text`、`rule_id`；
- 四类解释：`affirmed`、`negated`、`planned`、`ambiguous`；
- 按逗号、分号、`and`／`but`／`while` 等分成局部作用域，逐技能关联该
  分句自己的主语、动作、否定和未来意图；不能把整句的 `I`、否定或计划
  扩散给所有技能；
- 省略主语的列表／否定只在能安全继承最近的第一人称作用域时继承，否则
  保守为 ambiguous；第三人称技能保持 ambiguous，不提供经历来源确认；
- 不推断熟练度，不调用模型、Python 服务或外部分析 API；
- `en` 才抽取；`other`／`unknown` 返回 `language_notice=true` 和空候选，
  仍保留手动选择 canonical 技能入口；
- 经历长度最多 5000 字符，数据库同时约束新写入。

已知边界：语言检测依据文字脚本和非 ASCII 拉丁字符；纯 ASCII 拼写的某些
非英文文本可能被判为 `en`。这不会被当作“识别正确”，候选仍需用户确认；
A3 未引入语言字段到共享 experience 合同。

### 3.2 课程页与个人画像

- `#/courses`：
  - 展示课程 canonical ID、名称、官方链接、学年、核实时间、先修说明、
    映射证据和候选技能；
  - 未登录可浏览；未配置 Supabase 时明确提示，不能保存；
  - 登录后“我已完成该课程”只保存 `profiles.completed_course_ids`，不写
    `user_skills`；
  - 课程候选默认不勾选；确认按钮只在课程已标记完成且用户选中技能后
    可用；
  - 撤回课程前显示将删除的课程来源技能数，明确说明其他来源保留。
- `#/profile`：
  - 新增、编辑、删除本人经历；文本仅经登录用户 RLS 会话保存；
  - 保存经历、编辑或抽取都不会自动确认技能；
  - 显示每段候选技能的原文证据、rule_id 和四类解释；
  - 只有 affirmed 候选提供“从该经历确认”按钮；negated／planned／
    ambiguous 明确说明不能作为本人掌握证据，只能走手动自述；
  - 手动添加只能从共享技能目录选择 canonical ID，不创建伪造 ID；
  - 已确认技能显示来源课程／经历原文摘要／手动、确认时间，可撤销；
  - 未知旧课程／技能 ID 保留并标注，不自动删除；
  - 账号页保留 Auth 与显示名称流程，原始课程 ID 文本输入由课程页取代。

## 五、账号、状态与迟到响应隔离

### 5.1 F1 根因和修复

独立复核复现：原先整句只计算一次 first-person／negation／future，再把同一
interpretation 分配给句中所有技能，导致 `My teammate used Python and I
used Excel.` 的 Python 获得 affirmed 和经历确认入口。

修复后按局部子句匹配技能；每个子句独立判断主语作用域、否定和计划范围。
只有以下情况可继承第一人称：省略主语的技能列表（如 `I used Python, SQL,
Excel`）或明确省略的否定／计划片段（如 `but not SQL`、`and plan to learn
SQL`）。出现第三人称主语、另一个名词主语或无法确定归属时保守为
ambiguous。原文整句仍作为 `evidence_text`，规则版本和 canonical ID 未改。

### 5.2 F2 根因和修复

独立复核复现：`profileController.save()` 的 UPDATE 错误、回读错误与
Promise rejection 在返回前没有比较请求代次，课程页又直接展示失败；旧 A
响应因此可写到换号后的页面。

修复后 UPDATE 完成、回读完成和 catch 都先比较捕获的 generation 与实时
generation，再检查错误；所有 stale 结果都带 `staleOwner: true`，包括
失败结果。账号表单视图按实时 user.id 重建（key 不含语言）；退出／换号时
旧 hook 的清理会把控制器 identity 置空并推进 generation。课程页只在结果
不是 stale 时修改 notice/error/busy，旧组件卸载后也不能写回新账号。

## 十、归属后续修复（2026-10-29，F1 同类错误收尾）

### 10.1 根因

2026-10-28 复核确认：局部子句修复只覆盖跨分句场景；同一片段内
"I + 他人 use/using" 仍被整体判为第一人称——`classifyClause` 只要片段含
I 就把主语作用域定为 first，再以整句级 `AFFIRMED_USE.test` 进入
affirmed，从未证明该 use 动作的执行者是本人。含姓名主语（如 Alex）时
第三人称模式也不命中，同样误判。

修复改为**逐技能执行者归属**：对片段内每个技能提及，先定位其前面最近
的 use 动词（governing verb），再从该动词位置向前回溯最近的执行者候选
——第一人称代词、第三人称模式或大写人名（排除技能名、动词形、介词短语
如 "in January"）。执行者可靠解析为第一人称才允许 affirmed；观察／要求／
转述他人使用、姓名等无法安全解析的嵌套主语一律保守 ambiguous；未命中
use 动词的提及不再凭词共现进入 affirmed。省略主语列表与否定／计划的
安全继承规则、整句 evidence_text、canonical ID、规则版本 1.0.0、
四类解释与手动确认语义全部未变；已通过的 F2 修复未动。

本轮还修复了实现过程中的一个缺陷：人名匹配正则若带大小写不敏感标志，
会把普通词对（"have not"）当作人名抢走归属；人名匹配必须大小写敏感，
并排除 I/we 等第一人称代词。
