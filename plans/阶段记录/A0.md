## 三、技术方案要点

1. **依赖固定**：react 19.3.1、react-dom 19.3.1、react-router-dom 7.18.4、
   ajv 8.20.0、ajv-formats 3.0.1；dev：vite 7.3.7、@vitejs/plugin-react 5.2.0、
   typescript 5.9.3、vitest 4.1.12、@types/react 19.3.0、@types/react-dom 19.3.0、
   @types/node 26.6.5（全部精确版本 + package-lock.json）。Node ≥ 22.12
   为 Vite 7 官方要求。未在根目录另建重复项目。
2. **运行时校验层**（`web/src/data/validation.ts`）：ajv Draft 2020-12
   加载 8 个上游 schema 编译 bundle 校验器（ajv `strict: false` 仅为关闭
   schema 作者侧 lint，不影响数据校验语义；上游 schema 原样未改），
   另实现合同 README 要求的交叉检查：引用（全部 skill_ids 指向技能目录）、
   重复 ID（五类实体 + source+source_job_id）、sample_count 与
   market_jobs 数量一致、时间顺序（采集/发布窗口、first_seen≤last_seen）、
   公开数据边界（禁用私有字段名递归扫描）。任何问题 → 整包拒收，
   无部分展示、无暗中替换。
3. **SYNTHETIC 标记**：在 `src/data/sources.ts` 前端来源配置声明
   `synthetic: true`，页面常驻横幅 + 徽章；冻结合同文件未添加字段。
4. **枚举**：八类角色等全部使用共同枚举；`src/data/labels.ts` 只加
   显示标签（中英），canonical ID 始终可见，翻译不改变内部值。
5. **状态**：loading（aria-live）、network error（可重试）、rejected
   （逐条列出校验问题 + 重试）、empty（总提示 + 五个分区空状态）、
   旧数据提示（`staleness.ts`，阈值默认 180 天，仅由 manifest
   generated_at 与当前时钟计算）。
6. **时间保真**：生成/采集/发布时间按包内原始字符串显示并标注精度
   （UTC 精确时间 / 仅日期 / 未知），不使用构建或查看时间冒充。
7. **i18n**：默认英文，右上角一键切换中文；URL `?lang=` 与 localStorage
   同步；`<html lang>` 同步；role_id、skill_id、路由与筛选值不翻译。
8. **无凭据运行**：无需任何 API key；Supabase 仅在 web/README.md 记录
   A1 接入方案，本轮无代码、无迁移、无 RLS。
9. 未接入 processed1.zip / processed2.zip，未运行采集，未消耗招聘 API
   额度，未接入任何运行时大模型。

- 导航：7 个导航项、当前页高亮、占位页明确"尚未实现+计划任务号+不模拟
  任何功能"；页标题随路由与语言联动（本轮发现并修复：初始 hash 为空时
  标题误报 404；集中式标题在路由切换下不可靠，改为页面级 `usePageTitle`）。
- 中英文切换：页面/导航/提示/控件/页标题同步；`data_analyst`、`python`、
  `sql` 等 canonical ID 保持；职位原文与来源证据保留英文；`?lang=`、
  localStorage、`<html lang>`（en/zh-CN）三处同步；切换后当前页、已加载数
  与状态保持。
- 键盘操作：Tab 至单选组、方向键/空格切换数据包生效（radio 原生键盘语义）；
  跳转链接、aria-live 状态区、语义化表格/定义列表齐备。
- 手机布局：390px 无页面级横向溢出（导航为设计内横向滚动），manifest 与
  卡片单列排布；截图存于被忽略的 `artifacts/qa-a0/`（3 张）。
- 错误恢复：损坏包 → 拒收面板（9 条具体 schema 问题：非 UTC 时间、
  role_subtype 约束、description 矛盾）→ 切回有效包完整恢复（4 卡片+5 技能）；
  空包 → 总空状态+五分区空状态、样本数 0。
- 排障记录：验收中发现嵌入式浏览器 HTTP 缓存提供旧模块导致"修改不生效"
  的假象，已在 vite dev 配置加 `Cache-Control: no-store`（仅 dev 响应头，
  与生产构建无关），干净环境下全量回归通过。

## 六、人工验收步骤（供项目所有者复核）

1. `cd web && npm ci && npm run dev`，打开控制台给出的地址（默认
   http://localhost:5173）。
2. 首页核对"已实现/未实现"清单措辞是否如实；顶部应有 SYNTHETIC 常驻提示。
3. 进入"样例数据（只读）"：默认有效包应有 1 岗位、5 技能、1 课程、
   1 资源、1 机会；核对时间均显示为包内原始值。
4. 切换"空包"与"损坏包"：空包应显示各分区空状态；损坏包应整体拒收并
   列出问题，不得显示任何数据。
5. 右上角 中文/English 切换：全站文字应切换，`data_analyst`、`python` 等
   ID 与当前页面/已加载数据不变；刷新后语言保持。
6. 仅用键盘（Tab/方向键/空格）完成数据包切换。
7. 浏览器窗口缩到手机宽度（约 390px）检查布局与横向滚动导航。
8. `npm run build` 确认生产构建通过（可选）。
