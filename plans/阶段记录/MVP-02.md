## 二 输入问题与处理决定

MVP-01 的岗位标题均为 Artificial example，其 `fixture_expected_role/stage` 是测试预期元数据。它们不能作为分类证据，否则答案会循环进入算法。原数据和原答案保持不变；旧 manifest 仍可导入，但尝试分析时明确报 `ANALYSIS_CONFIG_UNSUPPORTED`，不把声明中的预期当可执行分类。

本轮在 `data/synthetic/inputs/mvp02-v1/` 独立创建带明确人工标题的输入，例如 Junior Data Analyst、Junior Business Intelligence Analyst，保留原设计的描述、缺失、99/100 字符边界和重复观察，并移除预期角色字段。新输入位于既有 raw 目录之外，没有改写原 raw。

新输入与答案分别编写：`tests/fixtures/mvp02_expected.json` 固定 10 个岗位的角色、阶段、正文可分析状态和技能集合；既有 `data/synthetic/expected-mvp02.json` 提供原先独立写定的算术答案。处理模块不读取这两个文件或预期标签字段。执行和核对属于代理编写样例及自动测试，不是真人标注或岗位人工复核。

## 四 固定规则与可复算口径

| 项目 | 本轮固定实现 |
| --- | --- |
| 契约/处理器 | utsc-contract-1.0 / utsc-analysis-1；实际代码 SHA-256 与依赖见 `artifacts/mvp-02/runtime.json` |
| 分类 | title-classification-2；五个方向、三阶段从标题提议，记录匹配片段和字符位置；资深、多个角色/阶段、初级与已匹配至少 3 年经验冲突待审 |
| 范围外 | 配置明确列出的 Product/Operations/Risk/Financial/Finance Analyst 等标题无支持方向时排除；其余未检出保留待审，不强行归类 |
| 正文 | text-clean-1：实体解码、HTML 正文与空白清理；至少 100 个 Unicode 字符含内部空格；短、缺、纯 URL、空模板和可读性未确认不进 D |
| 可读性 | 字母占比不足 35% 或替换字符超 5% 保守标未确认，不声称理解全部语义乱码；正文问题不自动剔除岗位 F |
| 日期 | 原采集时点为基准，0–35 天闭区间；缺、无效、未来、过旧发布排除；采集时点不可解释待审；保留 DATE/DATETIME 精度和时区，不用今天重筛 |
| 地点 | synthetic-area-map-2，仅人工 Toronto/Montreal 测试映射；原输入的 market_area 不替代映射；未知城市待审 |
| 技能 | synthetic-skills-1 / literal-word-matching-1；SQL 与 Structured Query Language 合并，Python 大小写合并，MySQL/pythonic 不误计 |
| 分母与比例 | `utsc-statistics-1`；D 是 F 中可分析正文数，M 是 D 中检出技能的唯一岗位数，率为 M/D；D=0 为 null；展示一位百分数，计算保留原精度 |

当同一 ID 中存在无法解释的采集观察或任一相同时点冲突，该组先待审，不因另一条旧观察可用就成为正式样本。国家/日期等明确排除条件在普通内容待审之前决定 EXCLUDED；分区只有一个主原因，多原因完整保留。所有候选保持在质量报告，缺 ID 的输入另列，计数满足 C=F+Q+E。
